SmartCare MLOps architecture

How patient vitals move from wearable devices to a live risk dashboard, and how models are trained and deployed.

Monitoring and observability are not implemented. DevSecOps scanning is a possible future enhancement.

Kafka Connect saves the raw stream to MinIO. Separately, Flink turns events into five-minute patient features. BentoML serves the XGBoost model, and predictions go to PostgreSQL for the Streamlit dashboard.

A trained XGBoost model and its metrics. The version number N is passed to the next jobs. If F1 is too low, the job fails and no alias is set.

The workflow trains and evaluates XGBoost, tracks metrics in MLflow, and registers a candidate model only if it meets the F1 threshold, which you set when you start the workflow (default 0.5).

One manually triggered GitHub Actions workflow runs seven jobs on a self-hosted runner: train, eval, build, push, deploy, smoke and promote. The build job also tests the image before it is pushed. If the rollout or the smoke test fails, the deployment is rolled back and the model is not promoted.
