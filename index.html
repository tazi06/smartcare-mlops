SmartCare MLOps architecture

How patient vitals move from wearable devices to a live risk dashboard, how models are trained and deployed, and which tool does what.

Lab project with simulated data. Monitoring and observability are not implemented yet. DevSecOps scanning is a possible future enhancement.

The workflow trains and evaluates XGBoost, tracks metrics in MLflow, and registers a candidate model only if it meets the F1 threshold, which you set when you start the workflow (default 0.5).

One manually triggered GitHub Actions workflow runs seven jobs on a self-hosted runner: train, eval, build, push, deploy, smoke and promote. The build job also tests the image before it is pushed. If the rollout or the smoke test fails, the deployment is rolled back and the model is not promoted.

6Tools and why we use them

Each card says what the tool is, why it is in this project, and where it runs.

Ingestion and streaming

Python simulator

What A script that makes fake wearable events and the list of crises.

Why No real patient data is needed, and we control volume, dirty data and the true labels.

vm-sim
Apache Kafka

What A log that holds the event stream.

Why One entry point for all data. Flink and MinIO read the same stream, and events are kept 3 days, so a slow reader loses nothing.

vm-kafka
Kafdrop

What A web page to look inside Kafka.

Why See topics, messages and consumer lag while debugging.

vm-kafka
Kafka Connect (S3 sink)

What Copies Kafka topics to MinIO with no code.

Why Keeps a raw copy for training, in folders by event date.

vm-kafka
Apache Flink

What A stream processor that remembers state.

Why Five-minute windows per patient need memory and event time. BentoML cannot do this.

vm-flink

Storage and batch

MinIO

What Object storage with the S3 API, run by us.

Why One place for raw events, training data and MLflow files.

vm-data
Apache Airflow

What A scheduler for pipelines.

Why Runs the ETL day by day, retries failures and keeps a history. It does the ETL only, not the training.

vm-mlops
DuckDB

What A SQL engine inside the Python process.

Why Reads JSON and Parquet in MinIO directly and is fast on one small machine, so Spark is not needed.

Inside Airflow tasks
Parquet

What A columnar file format.

Why Small, typed and fast. Training reads only the columns it needs.

MinIO, clean-data

Model and serving

XGBoost

What A model made of many small decision trees.

Why Strong on tables of numbers, handles missing values, and scale_pos_weight helps with rare crises.

Trained on the runner, served in k3s
MLflow

What Tracks training runs and keeps model versions.

Why Every run is saved with its metrics. The aliases candidate and production show which version is which.

vm-mlops, files in MinIO
BentoML

What Turns the model into a REST API.

Why Gives input checks, health checks, metrics and workers with little code.

k3s pods on vm-serving
PostgreSQL

What A relational database.

Why Stores MLflow metadata, scores and alerts. The dashboard reads it with simple SQL.

vm-mlops
Streamlit

What A Python framework for web apps.

Why The live dashboard is one Python file and refreshes every 10 seconds.

vm-mlops

CI/CD and platform

GitHub Actions

What Runs the pipeline from the repository.

Why One click runs all seven jobs. A self-hosted runner inside the VPC is needed because MinIO, MLflow and k3s are private.

vm-runner
Docker and Docker Hub

What Image packaging and a private image store.

Why The image holds the code and the model, tagged with the model version, so a rollback is just an older tag.

Built on vm-runner
k3s (Kubernetes)

What A light Kubernetes.

Why Runs 2 copies, replaces them one by one on update, checks readiness, and rolls back on failure.

vm-serving
Google Cloud VPC

What A private network with 7 VMs and no public IPs.

Why Close to a real setup: services talk on private addresses, and SSH goes through IAP.
